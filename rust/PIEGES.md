# Pièges du workspace Rust

Relire avant de toucher à `rust/`. Une ligne par piège : motif → cause + quoi faire (date).

- ⚠️ `cargo` introuvable → il est dans `%USERPROFILE%\.cargo\bin`, hors PATH : l'appeler par son chemin complet depuis PowerShell (`verify.ps1` le trouve seul) (2026-11-14).
- ⚠️ Test de parité « could not run » ou import `psycopg2` en échec → le `python` du PATH (3.15) n'a pas les dépendances de 3.5 : poser `CSDM_REFERENCE_PYTHON` (ici `C:/Python314/python.exe`) (2026-11-14).
- ⚠️ Fichier de données restauré mais le binaire garde l'ancienne version → `Copy-Item` garde la date du fichier copié, cargo ne recompile pas un `include_str!` dont la date n'a pas bougé : toucher le fichier après toute restauration (`(Get-Item f).LastWriteTime = Get-Date`) ou restaurer par `git checkout` (2026-11-14).
- ⚠️ Nouveau fichier absent de `git status` → `status.showUntrackedFiles=no` dans le `.gitconfig` global de l'utilisateur : lister avec `git status --untracked-files=all`, ajouter par chemins explicites (2026-11-14).
- ⚠️ Contrôle des valeurs en dur muet sur un test, bavard sur du code → il cesse de lire un fichier à la première ligne `#[cfg(test)]` : garder le module de tests en fin de fichier ; un `const`/`static` est exempté jusqu'à la ligne qui finit par `;` (2026-11-14).
- ⚠️ Un mot ordinaire masqué `***` dans le journal ou un message → le masquage remplace toute occurrence d'un secret connu dans le texte libre (journal, messages, questions, erreurs) ; un mot de passe court peut être un mot courant : ne jamais tester l'absence d'un secret par sous-chaîne d'un texte entier, tester clés et valeurs. Les données d'état (`state`) ne sont jamais masquées par sous-chaîne, seulement par clé : sinon une clé de filtre contenant le mot (dans `_mf`) arrivait altérée à l'interface (2026-11-14).
- ⚠️ Un test lit les vrais réglages → tout test passe un dossier explicite (`SearchPlaces { explicit_root, .. }`, `tempfile`), jamais `SearchPlaces::from_env()` ; une racine explicite coupe toute autre recherche (2026-11-14).
- ⚠️ Mot de passe PostgreSQL en clair dans les presets 3.5 et dans `csdm_config.json` → ne jamais afficher ni copier ces fichiers dans un journal, un test ou un commit ; l'import s'éprouve sur copies (`tests/import_real.rs`, compte seulement) (2026-11-14).
- ⚠️ Script Python bloqué après `pg_ctl start` → le serveur lancé hérite des tuyaux d'un `subprocess.run(capture_output=True)` et ne les ferme jamais : lancer `pg_ctl start` avec stdin/stdout/stderr à `DEVNULL` et `-l <journal>` (2026-11-14).
- ⚠️ Lien de tag vers un tag absent dans la base de l'auteur (1 lien `checksum_tags` sans ligne `tags`, vu le 2026-11-14) → ne pas le prendre pour un effet d'une écriture : le banc T5 le relève dans la copie de départ et ne compte que les orphelins nouveaux (2026-11-14).
- ⚠️ Un tag « déjà posé » n'est pas un tag posé par le lot → `TagWriter::link` dit s'il a inséré ; l'annulation d'un lot (`TagSession::rollback`) ne retire que les liens insérés (3.5 retirait aussi les liens antérieurs) (2026-11-14).
- ⚠️ `initdb` : « n'a pas pu créer le répertoire <dossier> : File exists » sur un dossier fait par `tempfile.mkdtemp` → depuis Python 3.12.4, `mkdtemp` pose sous Windows une ACL protégée (SYSTEM, Administrateurs, DROITS DU PROPRIÉTAIRE) ; lancé d'un shell élevé (PowerShell de l'app), le propriétaire est le groupe Administrateurs, et `initdb` se relance avec un jeton où ce groupe est désactivé : il ne lit plus le dossier, son `stat` échoue, son `mkdir` rend « existe ». Depuis Git Bash (non élevé) le propriétaire est l'utilisateur, donc ça passe : un banc vu vert d'un seul shell n'est pas rejouable. Créer le dossier par `mkdir` simple sous TEMP (droits hérités) et rejouer tout banc depuis PowerShell aussi (2026-11-14).

- ⚠️ Test piloté : une sauvegarde différée part entre deux mouvements du pointeur → `egui_kittest` avance de 0,25 s par image par défaut : `with_step_dt(1/60)` (harnais `tests/common`) ; une infobulle demande d'attendre son délai (`Rig::wait`), pas `run()` (2026-11-14).
- ⚠️ Test piloté en mouvement complet : `Harness::run` dépasse ses pas → l'anneau du bouton principal redemande une image à chaque image : `run_steps(n)` quand la porte de mouvement est ouverte (2026-11-14).
- ⚠️ Glisser qui se lâche sans effet → egui oublie `press_origin` sur l'image du relâchement : garder le dernier déplacement dans l'état du geste et l'appliquer au lâcher (`grid.rs::Drag::travel`) (2026-11-14).
- ⚠️ Lignes de console collées → un `LayoutJob` jette tout caractère hors section : chaque caractère (sauts de ligne compris) appartient à une section (test `sections_cover_every_character_so_lines_stay_apart`) (2026-11-14).
- ⚠️ Chaîne brute coupée net (« expected at least one digit in exponent ») → `r#"…"#` se ferme sur le `"#` d'une couleur `"#2563EB"` : `r##"…"##` (2026-11-14).
- ⚠️ Rendu sans fenêtre (`.wgpu()`) : `STATUS_ACCESS_VIOLATION` → DX12 plante sur la machine de dev : le harnais pose `WGPU_BACKEND=gl` (2026-11-14).
- ⚠️ Champ de saisie qui ne reçoit rien en test → `type_text` envoie le texte au focus seulement : cliquer le champ, ou le focaliser comme 3.5 (`autoFocus` de la question, Annuler du dialogue) (2026-11-14).
- ⚠️ « Rien n'est sauvegardé » vérifié par l'absence d'un onglet dans `ui_sections` → la valeur par défaut de 3.5 contient déjà une disposition par onglet : comparer à `settings::defaults(None)["ui_sections"]` (2026-11-14).
- ⚠️ `cargo` « command not found » depuis Git Bash même avec le chemin complet → les exécutables de `.cargo\bin` sont des liens que seul PowerShell résout : lancer cargo depuis PowerShell (2026-11-14).
- ⚠️ Un correctif textuel du générateur de références « trouvé 0 fois » → deux remplacements de la même liste se recouvrent (le premier a déjà changé le texte du second) : compter les occurrences sur le texte d'origine et ne garder qu'une règle par motif (`tools/t3_golden_refs.py`, 2026-11-14).
- ⚠️ Requête refusée « table hors découverte » sur un `IS DISTINCT FROM 1` → la garde de `csdm-db` lisait tout mot après `FROM` comme une table ; elle saute désormais le `FROM` précédé de `DISTINCT` : relire `guard.rs` avant d'écrire une clause SQL inhabituelle (2026-11-14).
- ⚠️ Banc qui signale 1 ou 2 unités d'écart sur un flottant → serde_json sans la fonction `float_roundtrip` lit mal certains nombres écrits par Python ; ce n'est pas le moteur : comparer à 2 ulp près et compter ces cas (`examples/t3_golden.rs`, 2026-11-14).
- ⚠️ Champ que 3.5 lit sans jamais le poser (`_chk`, `round_idx` des kills) → le défaut est dans 3.5 (correction (g) de T3) : chercher qui écrit une clé avant de porter sa lecture (2026-11-14).
- ⚠️ Script Python « garde le CRLF s'il y en a » qui réécrit le fichier en LF → `Path.read_text()` traduit les fins de ligne Windows à la lecture, la détection ne les voit jamais : détecter et réécrire sur `read_bytes()`/`write_bytes()`, puis comparer aux octets de HEAD (T4, 2026-11-14).
- ⚠️ Un test ou un enregistreur qui tuerait le vrai CS2 → KILL et le délai d'enregistrement tuent par nom tout processus `cs2_process_name` de la machine, où l'auteur joue : le faux CS2 porte un nom unique (`fakecs2_<pid>.exe`) passé en `cs2_process_name`, et `cs2_send_to_back` est faux dans tout test (il pousse la fenêtre de tout programme dont le nom contient « cs2 ») (T4, 2026-11-14).
- ⚠️ Faux programme de test qui rend le code 101 sans rien dire → il a paniqué, mais sa sortie d'erreur part dans le tube que lit le lanceur : lancer la copie à la main dans un dossier semblable pour lire la panique (T4, 2026-11-14).
- ⚠️ Banc qui rejoue des cas de référence et écrit chez l'auteur → les fichiers de cas gardent les réglages bruts, le générateur ajoute ses réglages forcés (chemins jetables, pauses à 0) au moment de jouer (`meta.json` « overrides ») : le banc Rust doit appliquer les mêmes, et une garde refuse tout chemin hors du dossier jetable (`examples/support/golden_case.rs`). Vu en T4 : 198 dossiers vides créés dans le vrai `Vidéos\CSDM Batch Clips`, retirés (2026-11-14).
- ⚠️ Banc qui dit « same » partout → le verdict par cas cherchait une clé (cas + passe) différente de celle notée en échec (cas) : un banc neuf se vérifie d'abord sur un écart provoqué (T4, 2026-11-14).
- ⚠️ Carte qui redemande une image sans fin (`grid.rs` « Content heights apply on the next frame ») → une rangée `ui.with_layout(Layout::right_to_left(..))` prend toute la hauteur disponible, la hauteur mesurée dépend alors de la carte et oscille : borner la rangée à son contenu, `ui.allocate_ui_with_layout(vec2(ui.available_width(), 0.0), layout, …)` (2026-11-14).
- ⚠️ `get_by_label` ambigu (« Export », « Cancel ») → la console et les dialogues portent les mêmes mots : donner au contrôle d’une carte un nom accessible distinct (`chip(.., Some("Export tags"), ..)`), texte visible inchangé (2026-11-14).
- ⚠️ Test piloté : un clic sur une carte basse est sans effet → `kittest` clique à l'endroit dessiné, hors de la fenêtre si la carte est sous le bord : fenêtre de test assez haute pour tout l'onglet (`tests/settings.rs`, 1600 × 3200), et la remettre après un bouton qui redimensionne la fenêtre (Apply, Auto) (2026-11-14).
- ⚠️ Test piloté : taper dans un champ déjà rempli ajoute au texte → sélectionner d'abord (Ctrl+A, `replace_in` de `tests/settings.rs`) (2026-11-14).
- ⚠️ « Found two or more nodes » sur un interrupteur → la piste et ses mots étaient deux widgets, chacun avec le même nom : un seul widget pour la piste et les mots (`tabs/settings/controls.rs::switch`) (2026-11-14).
- ⚠️ Contrôle des glyphes qui panique « is a directory » → il lisait `src/` à plat ; un onglet dans `src/tabs/<onglet>/` exige le parcours des sous-dossiers (corrigé dans `paint.rs`) (2026-11-14).
- ⚠️ Fichier Rust tout entier « modifié » après une édition par script Python → `open(p, 'w')` en mode texte sous Windows écrit des CRLF : lire et écrire avec `newline=''` pour garder les fins de ligne du fichier (2026-11-14).
- ⚠️ Réglage appliqué à chaque frappe (police : un message par lettre) → n'appliquer qu'une fois la saisie posée (`Link::save_due_in(now).is_none()`) (2026-11-14).
- ⚠️ Test piloté : `is_selected()` vaut `None` sur une case ou une rangée cochable → `WidgetInfo::selected` d'egui devient l'état « toggled » d'AccessKit : lire `accesskit_node().toggled()` (`tests/editing.rs::Rig::checked`) (2026-11-16).
- ⚠️ Test piloté : le champ d'une question du moteur est introuvable juste après le clic → la question vient du fil du moteur, quelques images plus tard : avancer jusqu'à voir son libellé (`Rig::wait_label`), et lire le libellé dans le moteur (« Preset name: », pas celui d'un scénario écrit à la main) (2026-11-16).
- ⚠️ Zoom ancré de la frise : la seconde sous le pointeur glisse de quelques pixels → le défilement s'arrête à la fin du contenu (comme un navigateur) : près de la fin de la démo la plus longue l'ancre ne peut pas tenir ; ce n'est pas un défaut du calcul, éprouver l'ancrage sur un clip loin de la fin (2026-11-16).
- ⚠️ Clips d'aperçu sans événement dans l'interface → l'aperçu du moteur Rust nomme les événements d'un clip par leur position dans `events[démo]` (ou `{"copy": …}`), 3.5 les donnait en place : passer par `csdm_core::editing::Preview::from_ready`, jamais relire la charge à la main (2026-11-16).
- ⚠️ Banc figé sur SAVE en mode édition → `SettingsEngine` (synchrone) attend la réponse à sa propre question « nom du preset » : faire tourner `SettingsHome` sur son fil, comme `RealEngine` (`tests/editing.rs::rig`) (2026-11-16).
- ⚠️ Décalage imposé à une zone de défilement (zoom) qui glisse de dizaines de pixels les images suivantes → egui juge ce décalage contre la taille du contenu de l'image précédente : au-delà, il le prend pour un étirement élastique, le ramène et laisse une vitesse qui continue de glisser ; couper l'élastique de la zone (`spacing.scroll.kinetic.rubber_band = false`, `tabs/editing/timeline.rs`) (2026-11-16).
- ⚠️ Centaines de `csdm_*.json` laissés dans `%TEMP%` après un banc du lot → le fichier de job s'efface 10 s après son essai, sur un fil que la sortie du banc coupe : seuls ceux des 10 dernières secondes restent (314 après `t4_golden`) ; dans l'app, qui reste ouverte, ils partent. Après un banc, les retirer par leur date (fenêtre de fin du banc), jamais tout `csdm_*` (T4, 2026-11-16).
- ⚠️ Test de processus qui échoue une fois sur quelques passages (« 1 of 2 wrote their id », code 101 du faux CLI) → les tests d'un même binaire tournent en parallèle et tuent CS2 **par nom** (KILL, délai d'enregistrement) : un nom de faux CS2 commun au binaire (`fakecs2_<id du processus>`) faisait tuer le CS2 d'un test voisin, parfois pendant que son CLI le lançait (« Accès refusé », os error 5). Tout ce qu'un test tue par nom porte un nom propre au test (`tests/support/kit.rs`), et un faux programme qui échoue le dit sur sa sortie standard : sa panique, elle, n'arrive pas au test. Un test qui exige la sortie de tout l'arbre garde le jeu ouvert (`close_game_after` faux), sinon la fin du CLI coupe l'arbre avant que CS2 parle (T4, 2026-11-16).
- ⚠️ Test de bout en bout qui panique « No glyph for … » sur un nom de joueur → les polices de l'app n'avaient que le latin (Inter, Segoe UI) : un nom persan, chinois, coréen… s'affichait en carrés vides dans l'app et panique sous `egui_kittest` (garde « glyphe manquant » par défaut). Polices d'écritures en repli (`ui_values::FONT_SCRIPTS`, test `paint::players_names_in_other_scripts_have_glyphs`) ; ne jamais passer `allow_missing_glyphs()` pour faire taire la garde (2026-11-16).
- ⚠️ Test piloté : un choix de liste déroulante (`ComboBox`) cliqué sans effet → la liste est bornée à ~200 px et défile, l'option hors vue n'est pas sous le clic : `.height(ctx.content_rect().height())` montre tout, comme le `<select>` de 3.5 (`tabs/video/kit.rs::codec`) (T10, 2026-11-16).
- ⚠️ Onglet qui ne reçoit pas les tables du vrai moteur alors que ses tests passent → réponse fixe des tests écrite à la main sous `data`, vrai moteur sans `data` (`describe_filters`) : piloter les tests sur le vrai moteur (profil jetable, base à un port fermé, `tests/video.rs`) plutôt que sur une réponse recopiée (T10, 2026-11-16).
- ⚠️ `zerocopy`/`num-traits` `build.rs` échoue avec `rustc failed with status: exit code: 0xc0000142` sous `rustc 1.100+` → `CARGO_TARGET_DIR` sous `.claude/worktrees/...` ou trop profond fait échouer l'appel enfant à `rustc` sous Windows : poser `CARGO_TARGET_DIR` sur un dossier court hors dépôt (ex. `D:/rust-targets/<tranche>`) (2026-11-26).
